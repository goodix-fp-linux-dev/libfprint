# SecWhiteEncrypt - Exact Algorithm (Reverse Engineered)

**Source**: `Wbdi.dll` @ VMA `0x180005f30` (function `SecWhiteEncrypt` in `seccipher.c`)
**Verified**: Output matches known test vector exactly (96 bytes for 32-byte PSK input).

## Summary

SecWhiteEncrypt wraps AES-128-CBC with SHA-256-based key derivation and HMAC-SHA-256
authentication. Despite the "whitebox" name, the core crypto is standard; the whitebox
part is only used to derive a fixed 16-byte constant that salts the key derivation.

## Algorithm (step by step)

### Constants

```
WB_SALT    = b"123GOODIX"                                     # 9 bytes, in .rdata @ 0x1802302f8
WB_CONSTANT = bytes.fromhex("5cba6e25819518de2d53e96dc0347ab0")  # 16 bytes, generated by whitebox init
```

The `WB_CONSTANT` is produced by `fcn.1800085e0` from rotated "Goodix" ASCII bytes
processed through SHA-256 and CRC-32 table operations. Since its input is always zero,
it is a fixed constant.

### Input

- `psk` : plaintext data (typically 32 bytes)

### Step 1: Compute 4-byte nonce

The nonce is the input length encoded as a 4-byte little-endian integer:

```python
nonce = struct.pack('<I', len(psk))   # e.g., b'\x20\x00\x00\x00' for 32-byte input
```

Derived from the loop at `0x1800061e0`-`0x18000621f` which extracts bytes of `ebx`
(the input length register) at various bit shifts, producing an LE32 encoding.

### Step 2: First SHA-256 hash

```python
hash1 = SHA256(nonce + WB_SALT)       # SHA256(4-byte nonce || "123GOODIX")
```

Calls at `0x180006224` (sha256_starts), `0x180006236` (sha256_update with nonce, 4 bytes),
`0x18000624b` (sha256_update with "123GOODIX", 9 bytes), `0x180006257` (sha256_finish).

### Step 3: Modify hash1 byte 15 (nibble replacement)

```python
modified = bytearray(hash1[:16])
modified[15] = (hash1[15] & 0xF0) | (len(psk) & 0x0F)
```

At `0x18000625c`-`0x180006295`: extracts `hash1[15]`, XORs with input length,
masks low nibble, XORs back. Net effect: replaces low nibble of byte 15 with
low nibble of the input length.

### Step 4: Derive AES key via second SHA-256 hash

```python
hash2_input = modified_hash1_16 + bytes(48) + WB_CONSTANT   # 16 + 48 + 16 = 80 bytes
hash2 = SHA256(hash2_input)
aes_key = hash2[:16]                                         # First 16 bytes = AES-128 key
```

Calls at `0x1800062a7` (sha256_starts), `0x1800062b9` (sha256_update, 64 bytes from
`[rbp+0x30]` = modified_hash1 + 48 zero bytes), `0x1800062c8` (sha256_update, 16 bytes
from `[rbp+0x70]` = WB_CONSTANT), `0x1800062d4` (sha256_finish).

AES key set at `0x18000632c` via `mbedtls_cipher_setkey(ctx, hash2, 128, ENCRYPT)`.

### Step 5: Set AES IV

```python
iv = modified_hash1_16                                       # Same 16 bytes as output prefix
```

At `0x180006359`-`0x180006364`: memcpy of modified hash1[0:16] into the cipher
context IV field.

### Step 6: AES-128-CBC encrypt with PKCS7 padding

```python
padded_psk = pkcs7_pad(psk, block_size=16)
ciphertext = AES_128_CBC_encrypt(key=aes_key, iv=iv, data=padded_psk)
```

PKCS7 padding mode set at `0x180006107` (add_padding = `0x180007e70`,
get_padding = `0x180007ea0`). Cipher is `MBEDTLS_CIPHER_AES_128_CBC` (type 5),
looked up from the cipher table at `0x18022e660`.

### Step 7: HMAC-SHA256 authentication

```python
hmac_tag = HMAC_SHA256(key=hash2, data=ciphertext)          # Full 32-byte hash2 as HMAC key
```

HMAC setup at `0x1800062ef` via `mbedtls_md_hmac_starts(md_ctx, hash2, 32)`.
HMAC updates during cipher loop at `0x1800065cc`. HMAC finalization at
`0x1800068fb`-`0x18000692d` (inner finish, reinit with outer pad, finalize).

### Step 8: Build output

```python
output = modified_hash1_16 + ciphertext + hmac_tag           # 16 + 48 + 32 = 96 bytes
```

- `modified_hash1[0:16]` written at `0x18000629f`
- Ciphertext written starting at output+16 (`var_58h = output + 0x10` at `0x18000638e`)
- HMAC tag (32 bytes) written at `0x18000695a`-`0x180006969`
- Total length stored at `0x180006972`: `[r12] = r15 + 0x10`

### Output size

For a 32-byte PSK input:
- Nonce computation: 4 bytes (not in output)
- Modified hash1 prefix: 16 bytes
- Ciphertext: 48 bytes (32 + 16 PKCS7 padding, 3 AES blocks)
- HMAC-SHA256 tag: 32 bytes
- **Total: 96 bytes**

General formula: `16 + ceil((len(psk) + 1) / 16) * 16 + 32`

## Python Implementation

```python
import hashlib
import hmac
import struct
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.primitives import padding as crypto_padding

WB_SALT = b"123GOODIX"
WB_CONSTANT = bytes.fromhex("5cba6e25819518de2d53e96dc0347ab0")


def sec_white_encrypt(psk: bytes) -> bytes:
    """Exact replica of SecWhiteEncrypt from Wbdi.dll."""
    data_len = len(psk)

    # Step 1: nonce = LE32(len)
    nonce = struct.pack('<I', data_len)

    # Step 2: hash1 = SHA256(nonce || "123GOODIX")
    hash1 = hashlib.sha256(nonce + WB_SALT).digest()

    # Step 3: modify byte 15 - replace low nibble with len & 0x0F
    prefix = bytearray(hash1[:16])
    prefix[15] = (prefix[15] & 0xF0) | (data_len & 0x0F)
    prefix = bytes(prefix)

    # Step 4: hash2 = SHA256(prefix + zeros(48) + WB_CONSTANT)
    hash2 = hashlib.sha256(prefix + bytes(48) + WB_CONSTANT).digest()

    # Step 5: AES-128-CBC encrypt
    aes_key = hash2[:16]
    iv = prefix
    padder = crypto_padding.PKCS7(128).padder()
    padded = padder.update(psk) + padder.finalize()
    cipher = Cipher(algorithms.AES(aes_key), modes.CBC(iv))
    ct = cipher.encryptor().update(padded) + cipher.encryptor().finalize()
    # Note: must use single encryptor instance
    enc = Cipher(algorithms.AES(aes_key), modes.CBC(iv)).encryptor()
    ct = enc.update(padded) + enc.finalize()

    # Step 6: HMAC-SHA256(key=hash2, data=ciphertext)
    mac = hmac.new(hash2, ct, hashlib.sha256).digest()

    # Step 7: output = prefix(16) + ciphertext + hmac(32)
    return prefix + ct + mac
```

## WB_CONSTANT Derivation

The 16-byte constant `5cba6e25819518de2d53e96dc0347ab0` is generated by
`fcn.1800085e0` at DLL load time. The function:

1. Rotates ASCII bytes of "Goodix" (`47 6f 6f 64 69 78`) at 4 different
   shift amounts (1/7, 3/5, 5/3, 7/1) producing a 24-byte table.
2. Feeds 3-byte subsets through SHA-256 and whitebox AES round operations
   (`fcn.180008110`, `fcn.180008210`, `fcn.180008430`).
3. Generates a CRC-32 lookup table at `0x1803143e0` (polynomial `0x04C11DB7`).
4. Combines results through CRC-32 and additional SHA-256/AES operations.

Since the input is always zeros (the 16-byte buffer is zeroed before the call),
the output is deterministic and constant across all invocations.

Extracted via Unicorn CPU emulation of the DLL function.
